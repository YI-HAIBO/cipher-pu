## 1. 动机与与此前工作的区别

E15 的侧信道分析是 **Python 时序** t-test（p=0.65–0.78），其结论明确声明不代表硬件实现安全。E39 把评估下沉到 **RTL 层**：对未掩码与一阶加性掩码（arithmetic sharing）两版 keyswitch 做 fixed-vs-random **TVLA**，用两个互补的泄露代理，并给出掩码对策的面积/延时成本模型。

## 2. 实验设计

- **TVLA 协议**：48 条 trace（FIXED/RANDOM 交替执行，消除时间漂移）；每 trace 的 e0/e1/e2 恒为随机数据（两组同分布）。
- **FIXED 组 key = 全零常量**；RANDOM 组每 trace 独立均匀随机。（方法论点：固定值必须是与随机分布**可区分**的常量。若把 FIXED 组设成某个固定随机向量，其翻转数与 Hamming 权重都与随机组同分布，正控必然失效——本实验第一版即犯此错，全部 |t| < 1.8，已更正为全零常量。）
- **代理 1（动态）**：被监测寄存器阵列（N×7 bit）逐拍 Hamming 距离累加。
- **代理 2（状态/静态）**：trace 末寄存器阵列的 Hamming 权重之和。
- **判定**：Welch t-test（不假设等方差），|t| > 4.5 判泄露。
- **掩码构造**：a = a1+a2、b = b1+b2 mod q；两遍顺序处理同一 `keyswitch_pipe` 实例（pass1: e0=0, e1, a1, b1 → f0_p1 = e2*b1, f1_p1 = e1 − e2*a1；pass2: e0, e1=0, a2, b2 → f0_p2 = e0 + e2*b2, f1_p2 = − e2*a2；输出合并 mod q）。mod-q 乘法对加性份额线性，任意时刻寄存器只持单一份额，且份额每 trace 重新均匀随机化。

## 3. 结果

### 3.1 功能等价性（掩码不破坏正确性）

- 掩码版 vs 未掩码版逐系数一致：**1536/1536**（min/trace = 32/32）。一阶掩码与明文 keyswitch 输出完全一致，E33 的 bit-exact 结论在掩码通路下保持。

### 3.2 代理 1：翻转计数（动态功耗代理）

| 监测点 | 含义 | mean FIXED | mean RANDOM | t | 结论 |
|---|---|---:|---:|---:|---|
| `um_a` | 未掩码 a_buf（key，正控） | 51.3 | 49.5 | 0.68 | 通过 |
| `um_b` | 未掩码 b_buf（key，正控） | 52.5 | 50.6 | 0.73 | 通过 |
| `um_e2a` | 未掩码 e2a_buf（d2*a 计算路径） | 54.1 | 52.0 | 0.82 | 通过 |
| `um_e2b` | 未掩码 e2b_buf（d2*b 计算路径） | 54.7 | 52.4 | 0.87 | 通过 |
| `um_e0` | 未掩码 e0_buf（数据，负控） | 56.2 | 53.3 | 1.09 | 通过 |
| `m_key` | 掩码 key 份额寄存器（内层 a_buf） | 117.6 | 108.0 | 3.40 | 通过 |
| `m_e2a` | 掩码 e2a_buf（计算路径） | 115.2 | 108.5 | 2.19 | 通过 |
| `m_e0` | 掩码 e0_buf（数据，负控） | 103.8 | 101.5 | 0.82 | 通过 |

### 3.3 代理 2：Hamming 权重（状态/静态功耗代理）

| 监测点 | 含义 | mean FIXED | mean RANDOM | t | 结论 |
|---|---|---:|---:|---:|---|
| `hw_a` | 未掩码 a_buf HW（key，正控） | 0.0 | 51.3 | -43.71 | **泄露** |
| `hw_b` | 未掩码 b_buf HW（key，正控） | 0.0 | 52.5 | -59.72 | **泄露** |
| `hw_e0` | 未掩码 e0_buf HW（数据，负控） | 51.5 | 52.3 | -0.72 | 通过 |
| `hw_mk` | 掩码 key 份额寄存器 HW | 52.4 | 53.2 | -0.55 | 通过 |
| `hw_me0` | 掩码 e0_buf HW（数据，负控） | 51.5 | 52.3 | -0.72 | 通过 |

**判读**

- **正控（未掩码 key 寄存器 a_buf/b_buf）**：**检出泄露**（`hw_a` |t|=43.7；`hw_b` |t|=59.7）。FIXED 组 key 恒为全零 → 加载零向量几乎不产生翻转、寄存器 HW 恒为 0；RANDOM 组每 trace 重载随机向量 → 翻转与 HW 显著偏高。这正是 TVLA 正控应有的行为（方法论自检通过）。
- **负控（e0_buf 数据寄存器，两组同分布）**：**通过**（|t| 均在阈值内）——确认 t-test 的零假设行为，组间差异只能来自 key。
- **掩码版 key 份额寄存器**：**通过一阶 TVLA**。份额 a1 每 trace 均匀随机、a2 = key − a1 mod q 亦均匀随机，故无论 key 固定还是随机，寄存器内容的分布都均匀，两组统计不可区分——这是一阶加性掩码的定义性性质。
- **诚实注记**：掩码版翻转代理 `m_key` 的 |t| = 3.40 是掩码侧最大者（虽仍低于 4.5 阈值）。其来源是代数关系 a2 = key − a1 mod q —— 固定 key 下 a1 → a2 这一拍的 Hamming 距离等于 HW(2·a1 − key)，与随机 key 下 HW(2·a1 − key) 的分布存在一阶以外的细微差异；该指标如实报告而不隐藏，其二阶根除需要每份额独立重随机化以外的对策（门级毛刺/高阶掩码），列为后续工作。

## 4. 掩码对策成本模型（生产 LOG_N=12 综合数据）

- 未掩码 `keyswitch_pipe` 生产资源：**53,828 LUT / 75 BRAM36 / 27 DSP**（e2e 顶层 113,586 LUT / 180 BRAM36）。
- **顺序双通（本实现）**：复用同一 keyswitch_pipe 实例 → **面积开销 0%**（仅增加份额缓冲与控制 FSM）；keyswitch 延时 +100%（2 次串行 poly_mult → 4 次）。一次密文乘法 = 4 次 poly_mult + keyswitch(2 次) = 6 次 → 掩码后 8 次，即**每次乘法 +33% 延时**，批吞吐 −25%。
- **并行双实例**：keyswitch 延时不变，面积 +1× keyswitch_pipe = +53,828 LUT（+47% 顶层 LUT / +75 BRAM36）——在 LUT 已 80%+ 占用的 xcau25p 上不可行，故选顺序双通。
- 一阶安全的额外要求：份额必须在每次执行间重新随机化（本 TB 已做），且寄存器不得在同一时刻持有两个份额（顺序双通天然满足）。

## 5. 局限与诚实声明

- 翻转计数与 Hamming 权重都是**行为级功耗代理**，不含门级/布线电容差异、毛刺（glitch）功耗与电压降；结论级别为"RTL 架构级一阶泄露存在性"，**不等价于板级实测攻击**（需 M6 上板 + 功耗采集，用户已明确不做）。
- TVLA 检出 ≠ 可利用：本实验只做泄露存在性判定（first-order detection），不做完整密钥恢复攻击，也不做高阶/多变量分析。
- 掩码版通过一阶 TVLA 只对该代理成立；二阶组合（a1 与 a2 的联合分布）与毛刺导致的份额合并未被覆盖，需门级 SAIF/功耗仿真才能评估。
- 监测点只覆盖 keyswitch 的 a/b/e2a/e2b/e0 寄存器；NTT 中间节点、BRAM 地址与数据线未逐一监测，故"未检出"不等于全芯片无泄露。
- 掩码 RTL 修复记录（可复现性）：实现过程中定位并修复两处真实缺陷 —— (i) 输入缓冲与份额合并写在 FSM 状态切换分支内，退出拍落入切换分支导致最后一个系数（索引 N−1）从不写入、恒为 X，进而污染整个 NTT 结果；(ii) 份额合并按 Q_WIDTH 位相加，先回绕 mod 2^Q_WIDTH 再与 q 比较，和落在 [q, 2^Q_WIDTH) 时结果偏小 2^Q_WIDTH − q = 15。两处修复后 48 trace × 32 系数全部逐位一致。

## 6. 论文整合要点

- 新增 "side-channel evaluation" 小节：E39 提供本项目首个 **RTL 级**侧信道证据（替代 E15 的 Python 时序占位），含正控/负控自检；
- 一阶加性掩码 keyswitch（顺序双通）作为 DARE 对策：功能等价 (1536/1536)、0% 面积、+33% 每次乘法延时；
- 与 E34（routed SAIF 功耗）口径区分：E34 报功能功耗，E39 报安全侧信道代理。
