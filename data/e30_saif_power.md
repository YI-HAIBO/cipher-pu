# E30: SAIF 驱动的门级动态功耗实测（M4）

**日期**: 2026-10-24
**里程碑**: M4（SAIF 功耗实测）
**器件**: xcau25p-ffvb676-1-e | **设计**: e2e_ckks_mult_ctrl_m4（N=4096, Q=45, 100 MHz, OOC 综合）

## 1. 动机：E13 的 0% 匹配问题

E13（ILA + XPower）得到的功耗基线 **1.182 W** 置信度仅 Medium：RTL 仿真 VCD 与 P&R 网表信号名匹配率 **0%（1/398,749）**，`read_saif` 完全失效，功耗实际上由默认 50% 翻转率假设支撑。本次实验目标：**用真实门级开关活动把功耗置信度提到 High**。

## 2. 方法：完整 SAIF 闭环流程

| 步骤 | 工具 | 产物 |
|------|------|------|
| ① 门级网表 | `write_verilog -mode funcsim`（从 OOC 综合 DCP，保留 RTL 网络名） | `gl_netlist.v` (67 MB) |
| ② DCP 网络名清单 | `get_nets -hierarchical` | `dcp_names.txt`（1,650,728 条） |
| ③ 门级仿真 | Icarus Verilog + Vivado unisims + BRAM 存根 + glbl | `gl.vcd`（4.8 GB，2,281,713 信号） |
| ④ VCD→SAIF | `vcd_to_saif.py`（剥 TB 层级、按 DCP 名过滤、总线按位展开） | `gl_power.saif`（143 MB，1,568,598 网络） |
| ⑤ 功耗分析 | Vivado `read_saif` + `report_power`（同一 OOC DCP） | `gl_power_rpt` |

**仿真场景**：N=4096 生产配置，2 次完整密文乘法（TB 自动 gear 控制），VCD 窗口 200 ns – 2 ms，100 MHz。

**为什么不用 xsim**：BASIC 许可证实例数上限 50k，而本设计展开到 211k 实例 → 改用 Icarus Verilog 做门级仿真（需剔除网表中 74,405 行加密 `pragma protect` 块、为 blk_mem_gen IP 生成存根）。

## 3. 结果

### 3.1 标注质量

| 指标 | 值 |
|------|-----|
| Design Nets Matched | **99%（409,222 / 412,845）** |
| 总体置信度 | **High** |
| 时钟节点活动 | High（>95%） |
| I/O 节点活动 | High（>95%） |
| 内部节点活动 | High（>25%） |

E13 的 0% 匹配被彻底解决（关键：**funcsim 网表保留 RTL 网络名** + **DCP 网络名过滤**，而 E13 用的是 RTL 仿真 VCD 对 P&R 网表）。

| 器件静态 | 0.458 W | 0.455 W | −0.7% |

| CLB Logic | 0.305 W | 0.007 W | −97.7% |

| Clocks | 0.019 W | 0.018 W | −5.3% |

对照 E13 的 1.182 W（P&R DCP + XPower 默认活动率）：SAIF 实测 0.824 W，**前值高估 30.1%**。

### 3.3 动态功耗结构（SAIF）

| 子系统 | 动态功耗 | 占比 |
|--------|--------:|----:|
| u_ksw（密钥切换，含 18 个 BRAM 缓冲） | 0.146 W | 39.6% |
| u_pm_shared（共享多项式乘法引擎） | 0.075 W | 20.3% |
| 18× IP 缓冲实例 | 0.162 W | 43.9% |

**Block RAM 占动态功耗 89.7%（0.331/0.369 W）**——设计是典型的存储受限（memory-bound）。

## 4. 关键发现

1. **99% 网络标注 solved E13**：置信度 Medium → High。方法论可复用（funcsim 网表 + DCP 网络名过滤 + Icarus 门级仿真）。
2. **默认 50% 翻转率把 CLB 逻辑功耗高估 43.6×**（0.305 → 0.007 W）：NTT 流水线访存受限，绝大多数 LUT 在多数周期空闲。**任何基于默认活动率的 FPGA HE 加速器功耗数字都应打折看待。**
3. **BRAM 是功耗主体（89.7% 动态）**：BRAM 时钟门控是最大的节能杠杆，而非逻辑优化。与 E26 的面积结论（BRAM ∝ N）一致——功耗同样随 N 线性上升。
4. **噪声监测闭环近乎零功耗**（0.003 W = 0.8% 动态）：SNR 反馈机制在功耗维度上"免费"，强化了运行时自适应卖点。
5. **u_ksw 是动态功耗热点**（39.6%），与 E24 rotation/bootstrap 分析一致——密钥切换是 CKKS 硬件实现的功耗瓶颈。

## 5. 诚实边界（写进论文）

1. **设计处于综合态（OOC），非 P&R**：实现状态置信度为 Low；布局布线后数值可能变化。
2. **OOC 子树功耗，非整芯片**：0.455 W 静态是 xcau25p 器件底噪，不含 I/O、PS、板级组件。
3. **活动数据来自 2 次密文乘法窗口**（funcsim 网表，BRAM 为存根），长时活动率可能略有差异。
4. **相对比较有效**（同一 DCP 上 SAIF vs 默认、vs E13），**绝对瓦数应表述为"综合级估算"**。

## 6. 对论文的影响

- §8.3「功耗估算」：1.182 W → **0.824 W（SAIF 驱动，High 置信度，99% 标注）**，ops/J 4.06e7 → 5.83e7
- 新增方法论段落：门级 SAIF 闭环流程（与 E13 的 0% 匹配教训对照）
